# 1.0 Platform Validation

This document separates automated build/package evidence from physical-device validation for the 1.0 release gate.

## Validation levels

- **Package/static** — Dart analyze/tests and Rust fmt/Clippy/tests pass.
- **Host build/link** — the example host compiles with the package and native processor for the target platform.
- **Physical device** — camera/gallery/crop/processor flows are exercised on real hardware where those flows are part of the claimed platform support.
- **Live calibration** — orientation/ROI/stability/auto-capture behavior is validated with recorded physical evidence on mobile camera platforms.

A host build is necessary release evidence, but it is not equivalent to physical-device validation.

The concrete 1.0 release record lives in `docs/1.0_PHYSICAL_VALIDATION_RECORD.md`.

## Current matrix

| Platform | Package/static | Host build/link | Physical/application validation | Live calibration |
| --- | --- | --- | --- | --- |
| Android | CI | CI: arm64 debug APK | baseline previously exercised; 1.0 re-validation pending | pending |
| iOS | CI | CI: debug build, no codesign | baseline previously exercised; 1.0 re-validation pending | pending |
| macOS | CI | CI: debug app build | Gallery/image processing only; 1.0 re-validation pending | n/a |

## Supported 1.0 platform scope

- **Android** — Camera + Gallery capture and Rust-backed processing.
- **iOS** — Camera + Gallery capture and Rust-backed processing.
- **macOS** — Gallery/image selection, manual crop, and Rust-backed processing only.

macOS camera capture is **not** part of the 1.0 support claim or release gate. Adding a macOS camera flow would be a separate feature with its own permission, plugin-behavior, UX, and physical-validation work.

## CI coverage

`.github/workflows/ci.yml` provides three independent jobs:

1. `flutter` on Ubuntu: package analyze/tests, example analyze, generated Android host, arm64 debug APK build.
2. `apple` on macOS: generated iOS/macOS hosts, iOS debug build without codesigning, macOS debug build.
3. `rust` on Ubuntu: formatting, Clippy with warnings denied, and Rust tests.

The generated hosts come from `tool/bootstrap_example_platforms.sh` so CI validates the same package integration contract without committing generated example platform directories.

## Physical release checklist

Before `validated Android/iOS/macOS support` is marked complete in the roadmap, record a fresh 1.0 validation pass for the relevant platform in `docs/1.0_PHYSICAL_VALIDATION_RECORD.md`.

### Android

- launch Camera and Gallery entry points
- capture portrait and landscape
- verify frame alignment/padding behavior
- confirm still capture -> crop -> Rust processing -> confirmation/result
- verify flash/torch/zoom controls on supported hardware
- verify processor output opens and has expected orientation
- run the SC-02/SC-04 calibration matrix before enabling production auto-capture thresholds

### iOS

- launch Camera and Gallery entry points
- confirm camera/photo-library permission prompts
- capture portrait and landscape
- confirm still capture -> crop -> Rust processing -> confirmation/result
- verify orientation/mirroring with the explicit live transform resolver
- confirm processor native library loads on device
- run the SC-02/SC-04 calibration matrix before enabling production auto-capture thresholds

### macOS — Gallery/image processing only

- launch the example app
- verify Gallery picker and user-selected-file entitlement
- crop a selected image
- confirm Rust processor native library loads
- process representative JPEG/PNG inputs and confirm output/orientation

No macOS camera test is required for the 1.0 platform-support gate because macOS camera capture is not currently claimed.

## Release-gate rule

The roadmap checkbox remains open until both conditions are met:

1. Android, iOS, and macOS host-build/link CI is green.
2. Fresh physical/application validation evidence for the 1.0 candidate is recorded for Android and iOS, with macOS Gallery/image-processing validation recorded separately.

Live auto-capture thresholds remain calibration-gated even after the general platform-support release gate closes.
