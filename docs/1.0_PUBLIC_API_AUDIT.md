# 1.0 Public API Audit

This document inventories the package API before a 1.0 stability promise is made.

## Stability rule

Anything exported by `lib/dxtr_card_scan.dart` is part of the primary package contract. Low-level orchestration that is intentionally available for custom integrations lives in `lib/dxtr_card_scan_advanced.dart` instead.

- **Primary** — normal application-facing API exported from `dxtr_card_scan.dart` and protected for 1.x source compatibility.
- **Advanced** — supported extension/integration API exported from `dxtr_card_scan_advanced.dart`. It remains public, but is deliberately separated from the primary compatibility surface.

Dart exports expose every public declaration in an exported file, so the boundary is maintained at declaration/file level rather than by headline class names alone.

## Compatibility observations

- Existing `const CardCaptureView(...)` construction is an established compatibility constraint and remains covered by regression tests.
- Built-in capture profiles continue to leave auto-capture disabled until physical calibration evidence promotes production thresholds.
- `CardCaptureResult.qualityMetadata` remains optional for source compatibility.
- Native scanner support remains dependency-injected; the package core does not acquire a mandatory VisionKit, ML Kit, or equivalent SDK dependency.
- CardTemplate coordinates remain defined over the perspective-corrected card image with runtime normalized-bound validation.
- `CardTemplateExtractor` remains a post-process over corrected encoded image bytes and does not introduce another detection/perspective-correction path.
- `test/public_api_boundary_test.dart` locks the root/advanced barrel split so low-level orchestration is not accidentally re-exported from the primary barrel.
- Public source naming was checked for unintended `Dxtr`-prefixed declarations; none remain.
